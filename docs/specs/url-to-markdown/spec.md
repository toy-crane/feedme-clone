# URL을 Markdown으로 바꿔 LLM에 넘기기

## 사용자에게 보이는 결과

개발자가 읽던 페이지의 주소를 붙여넣으면 광고와 네비게이션이 걷힌 본문을 Markdown으로 받는다. 화면에서 내용을 확인한 뒤 클립보드에 담거나 `.md` 파일로 내려받고, ChatGPT나 Claude의 새 대화를 열어 바로 붙여넣는다. 원하면 미리 준비된 프롬프트를 본문 앞에 붙일 수 있다.

## 범위

한 화면에서 입력, 변환, 결과 확인, 내보내기가 이어진다. 승인된 표면은
[prototype.html](./prototype.html)이다.

- 입력: URL 붙여넣기, 지우기로 초기 상태 복귀
- 변환: 본문과 메타데이터 추출
- 결과: 제목과 출처를 담은 헤더, 렌더링된 본문
- 내보내기: 결과 헤더 오른쪽 끝의 드롭다운 하나에 네 가지를 담는다
- 프롬프트: 프리셋 세 가지와 직접 입력
- 다크모드 토글

## 수용 기준

입력과 변환

- URL을 붙여넣고 변환하면 결과 영역에 페이지 제목과 출처가 헤더로 보이고, 그 아래에 본문이 렌더링된 모습으로 보인다.
- 원본 페이지의 광고, 네비게이션, 사이드바, 푸터는 결과에 포함되지 않는다.
- 변환이 진행되는 동안 진행 중이라는 것이 화면에 드러난다.
- 지우기를 누르면 입력과 결과가 모두 비워지고 처음 상태로 돌아간다.

내보내기

- 내보내기는 결과 헤더의 오른쪽 끝에 있는 버튼 하나로 열리는 메뉴에 모인다. 메뉴에는 Claude로 열기, ChatGPT로 열기, Markdown 복사, `.md` 파일로 저장이 이 순서로 담기고, 앞의 두 가지와 뒤의 두 가지를 구분선으로 나눈다.
- 메뉴는 바깥을 누르거나 Escape를 누르거나 항목을 고르면 닫힌다. 결과가 바뀌어도 닫힌다.
- Markdown 복사를 고르면 Markdown 원문이 클립보드에 담기고, 담겼다는 사실이 결과 헤더 바로 아래에 드러난다.
- `.md` 파일로 저장을 고르면 Markdown 원문이 파일로 저장된다.
- Claude로 열기 또는 ChatGPT로 열기를 고르면 Markdown 원문이 클립보드에 담기고, 해당 서비스의 새 대화 화면이 새 탭에서 열린다.
- 프롬프트를 고른 상태에서 LLM으로 열기를 고르면 클립보드 내용의 맨 앞에 그 문구가 붙는다.

프롬프트

- 프리셋은 요약해줘, 한국어로 번역해줘, 쉽게 설명해줘 세 가지다. 한 번에 하나만 선택되고, 선택된 것을 다시 누르면 해제된다.
- 직접 입력을 고르면 텍스트 입력이 나타나고, 입력한 문구가 프리셋 대신 본문 앞에 붙는다.
- 직접 입력한 문구는 저장되지 않는다. 페이지를 새로 열면 남아 있지 않다.
- 프롬프트를 고르지 않아도 LLM으로 열기가 동작하며, 이때는 본문만 전달된다.

실패

- URL 형식이 아닌 값을 넣으면 변환을 시도하지 않고 형식이 잘못되었음을 알린다. 이 경우에는 버튼을 두지 않는다. 입력을 고치는 것이 유일한 다음 행동이기 때문이다.
- 페이지를 가져오지 못하면(HTTP 오류, 네트워크 실패) 가져오지 못했다는 사실과 함께 주소를 확인하거나 다시 시도하라고 안내한다.
- 페이지는 가져왔지만 본문을 찾지 못하면 본문을 찾지 못했다는 사실과 함께 원본에서 직접 복사하라고 안내한다.
- 세 경우의 안내 문구는 서로 구별된다. 개발자가 자기 입력 문제인지 페이지 문제인지 판단할 수 있어야 한다.

화면

- 변환 중에는 결과와 같은 골격의 자리표시가 보인다. 제목, 출처, 본문 자리를 그대로 유지한다.
- 결과나 오류가 화면에 있는 동안에는 입력창 아래 안내 문구를 감춘다.
- 다크모드 토글이 있고, 선택한 모드는 다시 방문해도 유지된다.
- 좁은 화면에서 입력, 결과, 내보내기의 순서와 중요도가 보존된 채 세로로 쌓인다.

## 확정된 제약과 근거

- 본문과 메타데이터 추출은 defuddle을 사용한다. 사용자가 지정한 제약이다.
- 화면에는 렌더링된 모습을 보여주고, 복사·다운로드·LLM 전달에는 Markdown 원문을 쓴다.
- LLM에는 클립보드로 전달하고 본문을 URL 파라미터에 싣지 않는다. 근거는 [llm-handoff](../../decisions/llm-handoff.md)에 있다.
- 일반 UI는 [ui-composition](../../decisions/ui-composition.md)을 따른다.

## 가정

이 스펙을 쓰는 과정에서 두되 확인받지 않은 판단이다. 어긋나면 고친다.

- 저자 정보가 없는 페이지가 흔하다(react.dev에서 확인). 저자가 비어 있으면 그 자리를 비워 두는 대신 사이트명과 도메인으로 출처를 표시한다.
- 사이트명이 도메인에 이미 담겨 있으면 도메인만 보여 준다. `overreacted · overreacted.io`처럼 같은 말이 두 번 나오지 않게 한다.
- 메뉴 안에서는 항목 이름만으로 대상이 드러나야 하므로 "복사"가 아니라 "Markdown 복사", "다운로드"가 아니라 "`.md` 파일로 저장"으로 적는다.
- 프롬프트는 LLM으로 열기에만 붙는다. 복사와 다운로드는 순수 Markdown을 낸다.
- 이미지는 defuddle 기본 동작대로 결과에 남긴다.
- 다운로드 파일명은 페이지 제목에서 만든다.

## 범위 밖

- 변환 이력 저장과 재조회. `PRODUCT.md`에서 필요 여부를 미정으로 두었다.
- 여러 URL 동시 처리. 같은 이유로 미정이다.
- 로그인이 필요한 페이지 접근.
- 프롬프트 저장과 관리. 직접 입력은 1회용이라고 확정했다.

## 남은 위험

- 자바스크립트로만 그려지는 페이지는 본문이 빈 결과로 나온다(x.com에서 확인). 이 스펙은 안내로만 대응하며, 렌더링 후 추출은 다루지 않는다.
- ChatGPT와 Claude의 새 대화 주소가 바뀌면 열기 버튼이 깨진다. 로그아웃 상태에서 두 곳 모두 도착은 확인했지만 로그인 상태의 최종 화면은 확인하지 못했다.
- `PRODUCT.md`의 "결과는 클립보드로 나간다"는 경계가 `.md` 다운로드를 포함하지 않는다. 제품 정의를 넓힐지는 이 스펙 밖에서 정한다.
- 프롬프트 선택이 내보내기 버튼보다 아래에 놓인다. 프롬프트를 고른 뒤 다시 위로 올라가 내보내기를 열어야 하므로, 프롬프트를 지나치는 사용자가 나올 수 있다. 프로토타입 검토에서 이 배치로 확정했다.
