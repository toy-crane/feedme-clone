# LLM 전달 방식

## Decisions

- 변환한 본문을 LLM에 넘길 때는 클립보드에 담고 해당 서비스의 새 대화 화면을 새 탭으로 연다. 사용자가 붙여넣어 전송한다.
- 본문을 URL 쿼리 파라미터에 싣지 않는다.

## Boundaries

- 프롬프트 문구만 URL로 넘기는 방식도 쓰지 않는다. 프롬프트와 본문은 하나의 클립보드 내용으로 함께 전달한다.
- 사용자가 직접 붙여넣는 대신 서비스 API로 대화를 생성하는 방식을 금지하는 결정은 아니다. 계정 연결이 생기면 별도로 판단한다.

## Why

`?q=` 계열 파라미터는 길이 한도가 있다. Claude Desktop 링크는 약 14,000자에서 잘리고, URL 인코딩을 거치면 기술 문서 한 편이 그 한도를 쉽게 넘는다. 잘린 본문은 화면에 오류로 나타나지 않고 조용히 짧아진 채 LLM에 도착하므로, 사용자가 결과가 나빠진 이유를 알 수 없다.

클립보드 방식은 붙여넣기 한 번을 요구하는 대신 문서 길이와 무관하게 항상 온전한 본문을 전달한다. 이 제품이 없애려는 손품은 광고를 지우는 일이지 붙여넣기 자체가 아니므로, 붙여넣기 한 번은 제품 약속을 해치지 않는다.

## Reconsider when

- ChatGPT나 Claude가 길이 제한 없이 본문을 받는 공식 경로(딥링크, 확장 API 등)를 제공할 때
- 계정을 연결해 대화를 직접 생성하는 방향으로 제품 범위가 넓어질 때

## Still-rejected alternatives

- 프롬프트와 본문을 `?q=`에 함께 싣기 — 긴 문서가 경고 없이 잘리고 사용자가 알아채지 못한다. 위 재고 조건이 충족되면 다시 본다.
- 길이에 따라 URL과 클립보드를 자동으로 오가기 — 같은 버튼이 문서마다 다르게 동작해 무엇이 일어났는지 예측할 수 없다.

## Evidence worth preserving

- 로그아웃 상태에서 확인한 결과, `chatgpt.com/?q=`는 입력창에 반영되지 않고 다른 경로로 넘어갔다. `claude.ai/new?q=`는 로그인 화면으로 가면서 파라미터를 `returnTo`에 보존했다. 로그인 상태의 최종 동작은 확인하지 못했다.
