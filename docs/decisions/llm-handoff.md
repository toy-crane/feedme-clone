# URL 변환과 LLM 전달

## Decisions

- 본문 추출은 서버에서 defuddle(`defuddle/node`의 `Defuddle(document, url, { markdown: true })`)로 합니다. 브라우저에서는 CORS 때문에 다른 사이트의 HTML을 가져올 수 없습니다.
- 대상 사이트의 응답 상태가 오류(403, 404 등)이거나 접속할 수 없으면 실패로 처리합니다. 오류 페이지의 내용을 결과로 보여 주지 않습니다.
- ChatGPT·Claude로 넘길 때는 완성된 열기 주소(인코딩 후)가 8,000자 이하이면 `?q=` 주소로 열고, 넘으면 전체 텍스트를 클립보드에 복사한 뒤 빈 대화를 열고 붙여 넣으라고 안내합니다. 본문을 잘라서 전달하지 않습니다.
- 복사, 다운로드, LLM 전달은 같은 내보내기 텍스트(`# 제목`, 출처 URL, 본문)를 씁니다. 프롬프트는 LLM 전달에만 앞에 붙입니다.
- 프롬프트 칩과 ChatGPT·Claude 열기 버튼은 결과 카드 아래의 고정 바에 둡니다. 복사·다운로드는 결과 제목 옆에 둡니다.
- 직접 입력한 프롬프트는 저장하지 않습니다.

## Boundaries

- 로그인이 필요하거나 자바스크립트로만 그려지는 페이지는 다루지 않습니다. 헤드리스 렌더링과 LLM API 직접 호출도 범위 밖입니다.
- 8,000자는 실제 한도를 확인하지 못한 기본값입니다.

## Why

defuddle은 차단된 페이지(nytimes, HTTP 403)에서도 "Please enable JS and disable any ad blocker" 같은 문구를 본문으로 돌려줍니다. 응답 상태를 따로 보지 않으면 오류가 결과처럼 보입니다.

항상 클립보드를 쓰면 짧은 글에서도 매번 붙여 넣어야 하고, 항상 주소에 담으면 긴 글(6만 자 이상)이 잘리거나 열리지 않을 수 있습니다. 그래서 길이로 나눕니다.

## Reconsider when

- `chatgpt.com/?q=`, `claude.ai/new?q=`가 실제로 받는 길이를 로그인한 브라우저에서 확인하면 8,000자를 조정합니다. 아직 확인하지 못했습니다(claude.ai는 스크립트 요청을 403으로 막습니다).
- 두 서비스가 `?q=` 형식을 없애면 클립보드 방식만 남깁니다.

## Still-rejected alternatives

- 본문 위 패널 — 읽으며 내려가면 버튼이 사라집니다.
- 오른쪽 사이드 패널 — 좁은 화면에서 제목을 밀어 내립니다.
- 고정 하단 바는 휴대폰에서 본문을 일부 가리지만, 읽던 자리에서 바로 보낼 수 있어 채택했습니다.
